# MAP 索引约定

`.project/MAP.md` 记录目录、文件以及每一步需要的输入、脚本与输出，不替代当前任务或磁盘事实。AGENTS 只指向本文件，不另存目录快照；项目目标、范围和阶段写入 PROJECT。

## 登记方式

- 路径相对项目根，使用 `/`。从实际目录工具的结果取路径，不猜文件名。
- 单文件登记核对该文件是否存在；目录登记以 `/` 结尾，覆盖其下文件。目录登记不证明目录内每个预期文件都存在。
- 只登记关键资产与关系。目录覆盖和文件逐条登记按任务需要选，不要求全项目清零。
- doctor 识别字段 bullet（如输入、输出、脚本、参考及其缩进子 bullet）、`- 【登记】` 行和 `## 初扫文件清单` 段内 bullet 中的反引号路径。
- 散文、表格与代码围栏中的提及不算登记。只在表格中记录的依赖如需机器核对，应补一条字段或显式登记。
- 占位符、glob 模式仅提示为 `map_syntax_hint`，不当作已存在文件。已知目录使用真实目录登记；尚未生成的产物在计划段说明，不写成已存在的输出登记。
- .project/ 的辅助资料不作为业务资产登记；根目录 README/AGENTS 等若明确登记，照常核对，不能仅凭同名就全局豁免。
- 不登记项目范围外的路径。外部依赖在散文中说明，按当前任务的授权另行查证。

## 示例

````markdown
## 环节：报告编制
- 输入：`数据/已确认测算.xlsx`
- 脚本：`.project/scripts/build_report.py`
- 输出：`报告/年度计划.docx`
- 下游消费：汇报材料编制（待确认是否已采用）

## 环节：系统取数
- 中间产物：`数据/原始/`
````

正式交付产物登记对应的确切版本路径。所有项目脚本统一存放在 `.project/scripts/`；配置、原件与必须固定文件名的产物沿用项目规则。

## 更新与验证

维护本次任务涉及的输入、输出及重要依赖。初扫清单是文件存在的快照，不等于已核实上下游；整理进业务环节后移除对应的初扫条目，避免维护两份清单。清单超过 100 条时明确标注截断，不能声称完整。

版本工具与 doctor 共用登记识别规则。`register` 发现文件已登记或被已登记目录覆盖时，不再追加路径；只在缺少登记时写入“产物登记”段，不改写业务关系。MAP 不承担变更历史的去重，整理索引不影响 CHANGELOG 中已有的事件。

默认 doctor 检查登记是否存在，不要求全项目登记。用户要求检查覆盖率时使用 `--check-coverage`；目录登记会覆盖其子文件，该检查只能反映所选登记策略下的覆盖情况。索引过期时先定向检索实际路径，根据已授权的工作修正相关项。
