# 产物版本管理（必用）

正式交付产物必须采用以下版本命名，并使用版本工具登记已生成且已验证的文件：

```text
名称_v主.次_YYYYMMDD.ext
```

例如 `年度报告_v1.2_20261019.docx`。源代码、配置、外来原件与需要固定文件名的产物不套此规范。文件名含“副本”“最终版”不等于需要改名。版本跳号可合理存在，不视为业务错误。

所有项目脚本统一存放在 `.project/scripts/`，版本模块也位于该目录；不把项目脚本放到根目录或其他业务目录。初始化时固定复制 `.project/scripts/_version.py`，脚本位置只记录在新生成的 PROJECT 中，AGENTS 只保留资料导航。初始化不询问启用与否，也不传入启用或停用参数。已有 PROJECT 的项目事实由初始化器保留，执行初始化的 agent 应在本次授权内备份后定向补充或更新其脚本位置与版本管理段。产物生成并通过相应工具验证后，执行 `register` 登记。常用命令：

```powershell
python .project/scripts/_version.py new --dir "报告" --name "年度报告" --ext .docx --today 20261019
python .project/scripts/_version.py latest --dir "报告" --name "年度报告"
python .project/scripts/_version.py versions --dir "报告" --name "年度报告"
python .project/scripts/_version.py register "报告/年度报告_v1.0_20261019.docx" --note "已生成并验证初稿"
python .project/scripts/_version.py publish --note "按项目发布节奏整理台账" --today 20261019
```

- `new` 仅计算并打印目标路径，不创建文件、不写台账。用实际文档工具生成并验证产物后，用 `register` 登记；重复登记同一产物不重复追加流水。
- `latest` 按主版本、次版本、日期排序。同一逻辑名称有多种扩展名时停止并提示明确文件，不跨格式自动选取。需要复现、审计或用户指定版本时，使用确切路径。
- `next_version` 计算次版本 +1，次版本 99 后转入下一主版本的 0。结构大改是否升主版本由项目规则决定，工具不推断业务语义。
- `register` 仅登记已存在且符合所选版本格式的文件；辅助 MAP 和 CHANGELOG 必须已存在。MAP 按有效文件路径或目录覆盖去重，CHANGELOG 独立按产物路径对应的事件标识去重，已发布条目同样有效。不验证文件格式内部内容，该验证由相应产物技能完成。
- CHANGELOG 的自动条目包含日期、产物路径、该产物版本与变更说明，并附带用于去重的 HTML 事件标识。整理历史时保留标识；同一路径的再次登记用于补齐资料，不重复记录，不能代替实际内容变更记录。旧版无路径的流水无法可靠匹配产物，不自动推断或改写。
- `publish` 将“未发布”段的完整正文移到“已发布”段顶部，以 `### YYYY-MM-DD` 标记本轮记录；保留普通说明、列表、表格、子标题、注释与旧版流水，不从产物版本推导项目版本。只整理本地 CHANGELOG，不部署、不上传、不归档。只有当前请求需要发布台账时才执行；空段不改文件。
- 可选全局参数 --root "项目路径" 放在子命令前；未指定时由已复制模块的位置推导项目根。
- CLI 日期默认取执行环境日期；跨时区时传入用户当前日期 `--today YYYYMMDD`。`new` 和 `publish` 校验真实日期；`new` 拒绝越界目录与包含路径分隔符的逻辑名称。

库提供 `parse`、`latest`、`all_versions`、`next_version`、`rel`、`scan_all` 及台账辅助函数。模块在项目中复制后，由其所在辅助目录推导 ROOT；不要求所有脚本依赖它。文件改名、逻辑名变化或格式变化时应核查调用者。需要可复现的流程使用确定的输入版本。
